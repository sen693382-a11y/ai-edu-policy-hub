## 四、引用核验口径已修正（本轮最关键的一处改动）

**旧口径（V0.2-A）**：`quote` 只要在 `para_ids` 列出的任意一个段落中能找到，就算通过。
漏洞：模型把 A 段的句子挂到 B 段编号下，仍会被判"通过"——这正是"看着有依据、实际说的是别段"的错配。

**新口径（V0.2-B）**：一条依据必须"编号—片段"成对成立。

| 情形 | 旧口径 | 新口径 | 新口径判定说明 |
| --- | --- | --- | --- |
| 片段在它标注的段落里逐字出现 | 通过 | 通过 | 记录原文偏移、跨度、片段哈希、段落文本哈希 |
| 片段真实存在，但属于**别的段落**（多段并列时） | **通过（漏放）** | **不成立** | 报"错配引用"，并指出实际所在段落号 |
| 片段由相邻两段拼接而成 | 通过 | 不成立 | 报"跨段拼接"，指出是哪两段 |
| 片段被改写（非逐字） | 不成立 | 不成立 | 报"疑似改写或虚构" |
| 编号不存在 / 段落不可引用 / 无 evidence | 不成立 | 不成立 | 单列原因 |

自测 7 例（样例由脚本现场从段落索引取原文构造，**不是模型输出**）：

| 编号 | 构造情形 | 期望 | 实测 |
| --- | --- | --- | --- |
| T1 | 编号与片段正确配对 | 通过 | ✅ 通过，偏移已记录 |
| T2 | 片段属于 P003，却把 P001 一并列为依据（旧口径按"多段并集"会放行） | 不成立 | ✅ 判"错配引用，实际位于 JS-004-P003" |
| T3 | 编号 `JS-004-P999` 不存在 | 不成立 | ✅ 判"段落编号不存在" |
| T4 | 无 evidence | 不成立 | ✅ 判"无依据" |
| T5 | 引用中插入"（改写）" | 不成立 | ✅ 判"疑似改写或虚构" |
| T6 | P003 段尾 + P004 段首拼接 | 不成立 | ✅ 判"跨段拼接" |
| T7 | 引用仅 6 字，但确实逐字存在 | 通过+告警 | ✅ 通过，标注"支撑力偏弱" |

汇总：7 条中 2 条通过、5 条不成立（依据片段 2/6 逐字命中）；检出错配 2（T2 段落错配、T6 跨段拼接）、疑似改写 1（T5）。**结论：新口径确实更严，且不会把"逐字正确但过短"误杀，只告警。**

## 五、逐条语义准确性核查（表已生成，待人填）

程序只能证明"这句话在原文里逐字存在"，证明不了"这个结论说得对"。因此另建人工核查表，固定五个维度：

| 编号 | 维度 | 判定要点 |
| --- | --- | --- |
| D1 | 目标概括准确 | 指标数字（如实验区/实验校、人工智能学院数量）、覆盖范围、限定条件有无夸大或缩小 |
| D2 | 措施来自原文 | 措施是否由原文表述支撑，而非模型补进来的同类政策常识 |
| D3 | 时间节点准确 | 年份/期限与原文一致，未换算、未把任务挪到别的年份 |
| D4 | 未把规划写成已完成 | 原文是"到2027年""建设/建成"，结论不得写成"已建成/已实现/已覆盖" |
| D5 | 无原文外推断 | 无原文不支持的因果、程度、范围外推 |

表格形态：每条结论一行，附**被引段落全文**（人工不必再翻文件），五个维度各留 `pass / fail / doubt` 勾选位与说明栏。真实响应到达后运行一条命令即可生成正式核查表：

```
python assistant_v02/verify_citations.py --file JS-004 --response run1/response_JS-004.json
python assistant_v02/make_semantic_sheet.py --from citation_check.json --label "JS-004 首次实验"
# 人工填完后汇总
python assistant_v02/make_semantic_sheet.py --summarize semantic_check.json
```

当前已用自测数据跑通整条链路，产出 `semantic_check_selftest.json / .md`（表头明确标注"样例，非模型输出"），确认结构与字段可用。

## 九、止损规则（已写进流程，出现即停）

| 触发 | 处理 |
| --- | --- |
| 出现 1 条编造引用（编号不存在 / 片段原文找不到） | 记录失败原因，**停止**，不扩大实验 |
