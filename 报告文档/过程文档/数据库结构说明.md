# 数据库结构说明（阶段一 + 阶段二 · schema v6）

> 权威来源是 `backend/db/migrations/001~006.sql`，本文档是人工可读的说明。
> 数据库文件：`data/policy_hub.db`（SQLite 3.53.1，WAL，`PRAGMA foreign_keys=ON`）。

## 1. 总览

| 项 | 数量 | 来源 |
|---|---:|---|
| 普通表 | 20 | `001_init.sql`（17）+ `005`（`source_site_check`）+ `006`（`collection_candidate`、`collection_attempt`） |
| 视图 | 8 | `003`（5）+ `005`（`v_source_coverage`）+ `006`（`v_candidate_queue`、`v_collection_coverage`） |
| FTS5 虚表 | 1（`resource_fts`，trigram 中文分词） | `002_fts5.sql` |
| 触发器 | 7（3 个 FTS 同步 + 4 个 P0 真实性约束） | `002` / `004` |
| 迁移版本 | 6（`001_init` / `002_fts5` / `003_statistics_views` / `004_p0_verification_guards` / `005_source_site_verification` / `006_collection_candidates`） | `migrations.py` |

初始化实测（`docs/init_db_result.json`）：v1–v3 于 10:47:30 首次应用，v4 于 11:11:32 **增量应用**，前 3 个版本未重跑；26 地区 / 85 字典项 / 18 标签 / 55 来源站点 / 104 覆盖记录；**正式政策 0、资料 0**。

## 2. 迁移机制

| 机制 | 实现 |
|---|---|
| 版本记录 | `schema_migration(version, name, checksum, applied_at)` |
| 完整性 | 每个 SQL 文件计算 SHA-256；已应用版本的校验值被改动时拒绝启动（`test_migration_checksum_tamper_detection`） |
| 幂等 | 只执行 `version > max(applied)` 的迁移；重复运行不重建表、不重复种子 |
| 事务 | 单个迁移在事务内执行，失败整体回滚 |
| 目标版本 | `backend/config.py:SCHEMA_TARGET_VERSION = 6` |
| 命令 | `python scripts/init_db.py`（初始化/增量）、`--check`（只读检查）、`--force-reset`（危险，重建） |

## 4. 两张核心表

### 4.1 `policy`（PRD 4.1）

`uid` 唯一；`title` 必填；`document_number`、`issuing_agencies_json`、`jurisdiction_id`、`issued_date`（落款）、`effective_date`、`expiry_date`、`validity_status + validity_basis`、`direction`、`document_type`、`abstract` 均**允许 NULL**，不得由 AI 推测补齐。

- 状态：`review_status(pending/in_review/approved/rejected)` 与 `verification_status(verified/pending/failed/source_dead)` 分开记录。
- 版本：`version_group_id` + `version_seq` + `version_label` + `relation_type` + `supersedes_policy_id`，同一政策 v1/v2/修订/废止通知分别建行并归组。
- 隔离：`data_origin(UNSPECIFIED/REAL/TEST)`；`is_draft` 标记征求意见稿。

### 4.2 `resource`（PRD 4.2 + 新增 P0 全部溯源字段）

| P0 必需字段 | 列名 | 说明 |
|---|---|---|
| 具体官方原文页面 URL | `source_url` | 已核验时非空，卡片「查看官方原文」入口 |
| 实际发布机构 | `source_agency` | 与 `publisher` 分开 |
| 原始发文机关 | `original_issuer` | 转载时指向原始发文主体 |
| 来源性质 | `source_type` | 原始发布 / 官方转载 / 官方配套资料 |
| 官方网页发布日期 | `published_date` | 与落款日期 `policy.issued_date` 区分，另有 `retrieved_at` 采集时间 |
| 最近成功核验时间 | `verified_at` | 仅在核验通过后写入 |
| 核验状态 | `verification_status` | 已核验 / 待核验 / 核验失败 / 来源失效 |
| 官方附件 URL 列表 | `attachment_urls_json` | 默认 `[]`，可为空 |
| 本地副本路径 | `local_copy_path` | 相对路径，可为空 |
| 内容校验值 | `content_hash` | 正文或文件的 SHA-256，禁止占位值 |
| （附加）实际跳转 URL | `final_url` | 保留重定向结果，不自动编造替代链接 |

其他：`content_format`、`full_text`、`completeness_status`、`review_status`、`notes`、`is_draft`、`data_origin`。

## 5. 视图与三种统计口径

| 视图 | 作用 |
|---|---|
| `v_verified_resource` | 已核验 ∧ 已审核 ∧ `data_origin='REAL'` ∧ 有来源 URL ∧ 存在 `source_check.result='passed'` |
| `v_formal_policy` | **独立正式政策**：在上一视图基础上，要求该 Policy 挂有非草案、已核验的 `formal_policy` 原文资料；按 Policy 实体去重 |
| `v_resource_detail` | 资料卡片/详情页联表，输出地区、来源站点、白名单状态、中文类型标签 |
| `v_coverage` | 26 单位年度覆盖状态（含中文标签） |
| `v_policy_tag` | 政策多标签展开 |

| 口径 | 定义 | 生产库当前值 |
|---|---|---:|
| 独立正式政策数量 | `COUNT(*) FROM v_formal_policy` | 0 |
| 资料记录数量 | `COUNT(*) FROM resource` | 0 |
| 标签出现次数 | `policy_tag + resource_tag` 行数 | 0 |

## 6. 数据库级真实性触发器（迁移 004）

| 触发器 | 拦截行为 |
|---|---|
| `trg_resource_no_verified_on_insert` | 资料不允许带「已核验」状态直接入库 |
| `trg_resource_verified_requires_evidence` | 改为已核验时必须具备：来源 URL、跳转 URL、发布机构、原始发文机关、核验时间，且存在 `result='passed'`、HTTP 2xx、**四项内容比对全为 1** 的核验记录 |
| `trg_policy_no_verified_on_insert` | 政策实体不允许带「已核验」直接入库 |
| `trg_policy_verified_requires_original` | 政策改为已核验前必须存在已核验的正式政策原文资料 |

> 因此绕过 API 直接改库、采集程序批量写入、人工导入三条路径受同一约束。`HTTP 200 ≠ 已核验` 是数据库层强制规则，不只是代码约定。
> 另 3 个触发器（`002_fts5.sql`）在 `resource` 增删改时同步 `resource_fts` 索引。

## 7. 中文检索

`resource_fts` 使用 FTS5 `trigram` 分词器（外部内容表，避免正文重复存储），可命中任意连续 ≥3 字中文片段；仓储层对 2 字及以下关键词使用 `LIKE` 兜底。索引字段：`title / full_text / original_issuer / publisher`；发文字号与发文机关经 `v_resource_detail` 联表检索。实测见 `tests/test_05_api_search.py`。

## 8. 设计约定（为迁移预留）

1. 所有时间戳由应用层写 ISO 8601 文本，不用 SQLite 专有 `DEFAULT now()`。
2. 未知信息一律 NULL，不用 `""` / `"未知"` 字符串冒充。
3. 附件存相对路径，数据库不含绝对盘符，便于换对象存储。
4. SQL 全部参数化；固定枚举用 CHECK，字典驱动字段由仓储层校验。
5. 换 PostgreSQL 时：替换 `connection.py`、把编号 SQL 改写为 Alembic 迁移、把 FTS5 trigram 换成相应中文全文索引方案；业务表结构可平移。

## 9. 阶段二增量迁移（005 / 006）

**005_source_site_verification.sql（2A）**：给 `source_site` 增加机构名称/性质、登记域名、政策栏目和检索入口、原始与最终 URL、跳转链、确认依据、确认时间、证据快照路径与哈希、`can_host_original_policy`；新增 `source_site_check` 存每次核验日志与 `v_source_coverage` 视图。只有 `result='confirmed'` 才允许把站点标为「已确认」。

**006_collection_candidates.sql（2B）**：给 `collection_job` 增加 `run_mode / no_network_access / target_count / success_count / failure_count / promoted_count / finished_reason / plan_snapshot_json / started_by`；新增 `collection_candidate`（`source_url` 唯一保证同 URL 重采幂等；四项比对、白名单结论、页面/正文哈希、提取失败原因均随候选保存；候选默认 `pending`）、`collection_attempt`（每次尝试独立留痕）以及 `v_candidate_queue`、`v_collection_coverage` 视图。

**统计口径不变**：候选与待审核资料都不进入 `v_formal_policy`；只有 `approved + verified + REAL + 非草案 + 有已核验正式原文` 的 Policy 才计为正式政策。2B 离线夹具候选的 `data_origin='TEST'`，永不升级为已核验，也绝不写入生产库。
